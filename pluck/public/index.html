Pluck opens a real Chrome window next to the page you paste and lists every video stream that page asks for. Size, duration and resolution are read from the file itself. Then you take the one you want, in parallel chunks, as one MP4.

Paste the page address, not the file address.

  • Drives Chrome you already have
  • Nothing leaves this machine
  • No account, no ads

Keep only what you have the right to keep. Streams behind DRM or a paid login hand out encrypted bytes that no local tool can decrypt.

What it takes, and what comes back

MP4 · WEBM · MOVOne direct file
Pulled as parallel ranged chunks, each retried on its own, then joined byte for byte. The file you save is the file the server sent.
HLS · .m3u8A playlist of segments
Read, decrypted if it carries AES-128 keys, fetched six at a time in order, joined, and remuxed into a single MP4 with ffmpeg.
DASH · .mpdA manifest of fragments
Best video representation plus its separate audio adaptation, both fetched with their init segments and muxed into one file.

Playlists need ffmpeg on your path. Without it the raw transport stream is kept rather than the download being thrown away. DRM-protected streams are out of scope and nothing here pretends otherwise.

Three moves, then the file is yours.

  1. 01

    Paste the page

    Any address with a video in it. Pluck starts Chrome with a throwaway profile in your temp folder, so the window it shows you shares nothing with the browser you use every day.

  2. 02

    Click inside it like it is yours

    Scrolling, typing, pressing play: every click is forwarded to that window. Each stream the page requests lands in the signal list the moment it is asked for, and Pluck opens the bytes to read duration and resolution rather than guessing.

  3. 03

    Take the file

    Progressive files come down in parallel chunks with resume across retries. HLS and DASH playlists are fetched segment by segment, joined, and remuxed into a single MP4 with ffmpeg, audio track included.

  • EncryptionAES-128 HLS playlists
  • NeedsNode 22+, Chrome, ffmpeg for playlists
  • TracksSession log, popup and redirect blocking

Questions worth answering before you paste.

Is this another download site?

No. Pluck is one Node process on your own computer, talking to your own Chrome. There is no server farm, no queue, no upload of the page or the file, and no account to create.

Why do some videos never show up?

Pages that use DRM (Netflix, Disney+, most paid streaming) hand the player bytes that only that player can decrypt. Those never appear, and that is by design, not a bug to work around.

What happens to the Chrome window Pluck opens?

It runs with a fresh profile in your temp directory and is closed when the session ends. Whatever cookies, logins and history you build up in it disappear with it.

What is the timer counting?

How long the live window stays open: five minutes by default, and it shows in the strip above the monitor. There is no queue to wait in and no rate limit; the clock exists so a forgotten window does not keep Chrome running all afternoon.

Do downloads stop when the session ends?

No. A transfer you started keeps running and finishes in the transfers list. Only the window closes.

Do I need ffmpeg?

Only for HLS and DASH. Without it, Pluck still saves the raw transport stream so the download is not wasted. You just get a .ts instead of a .mp4.

A download failed with 403 or 404. Now what?

403 usually means the host checks where the request came from: keep Send session headers on so Pluck forwards the page's referer and cookies. 404 inside a playlist means the token in the address expired. Reload the page in the live window, let it detect the stream again, and start the download from the fresh signal.

Can I paste a video file address directly?

You can, but you get more out of a page: the live window is what makes players reveal the stream they are actually playing.
